Major Enhancements

Built-in Shapeshifting with Animated Token Transitions

The shapeshifting wizard is now a built-in system feature and no longer requires an addon module to be installed. Dropping a creature onto a character sheet always offers the shapeshift option alongside the mount and new companion option.

When a shapeshift or shape restoration occurs, the affected token now plays an animated morph transition using the native Foundry v14 TextureTransitionFilter. If the token texture changes, a smooth morph effect bridges the old and new appearance; if the texture stays the same, a swirl animation signals the transformation visually.

Native Payment Requests And Shared Transaction Summaries

Payment requests created by GMs can now be bundled into a single shared chat card instead of sending separate prompts for every actor.

The new flow uses Foundry's native query system instead of a custom socket-based request transport. This means the system can directly hand the payment decision to the designated owning user of each actor and collect the results back into one shared overview card.

Highlights of the new flow:

  • GM /pay and /getPaid requests can target multiple active character actors at once.
  • All recipients are tracked inside a single chat card with per-actor status information.
  • Requests are sent to the designated actor owner when one is available.
  • GM fallback controls remain available on the card for offline, unowned, rejected, or failed requests.
  • Merchant and trade notifications now feed into a shared transaction summary card instead of creating fragmented chat output.
  • The payment dialog from the chat helper menu, group sheet, and masters menu now shares a single consolidated layout with actor selection and an optional description field.

This upgrade makes payment handling much easier to follow in multiplayer sessions and aligns the implementation with the current Foundry API.

Query-Based Roll Requests

GM roll requests for skills, attributes, and regeneration now use the same Foundry query system as payment requests instead of the legacy clickable chat-link flow.

When a GM triggers a roll request from the masters menu, group sheet, /rq chat command, or a journal enricher, a unified dialog now opens with a searchable skill dropdown prefilled with the originating skill, a modifier input, and actor checkboxes to select which heroes should receive the request.

Highlights of the new flow:

  • One persistent chat card tracks all requested actors with live per-row status updates as results come back.
  • Requests are automatically dispatched to the designated actor owner, opening the real roll dialog on their client.
  • The card shows detailed result information including quality steps, critical successes, and regeneration values.
  • GMs can right-click any pending row on the card for a context menu with resend, roll on behalf, and skip actions.
  • A fallback roll button on each row lets players or the GM trigger the roll manually from the card.
  • Row actions are automatically hidden for users who have already completed their roll.

Calendar-Integrated Adventure Questlog

The calendar/campaign manager now includes a dedicated questlog tab for long-running adventure and campaign tracking, turning the existing calendar surface into a central place for events, dramatis personae, and overarching objectives.

Questlog entries are stored in dedicated dsaquestlog journal pages and can be registered per journal in the same way as calendar events and Dramatis Personae. Each quest can hold structured summaries, detailed notes, GM-only information, multi-step objectives, and in-world timeline information.

Highlights of the new questlog flow:

  • Adventure journals can expose questlog pages directly inside the calendar picker.
  • Quest entries support objective tracking for multi-session story arcs.
  • Timeline metadata such as start, target, and completion dates can be stored directly on the quest.
  • Quest entries can link back to calendar events and Dramatis Personae entries using stable embedded entry references.
  • GMs and players can use the same calendar surface to follow the current state of the adventure instead of splitting information across separate tools.

This upgrade establishes the questlog as a major campaign-management feature rather than a simple notes list and extends the calendar picker into a broader narrative control center.

Scene Regions Replace Measured Templates

Area-of-effect spells and auras now use the native Foundry v14 Scene Region system instead of custom MeasuredTemplate overlays. This brings significant improvements to both spell placement and aura management.

Spell templates placed from chat cards now use canvas.regions.placeRegion() for interactive placement with live green/red range feedback. Instant-duration spells create ephemeral regions that acquire targets and then disappear; maintained spells create persisted regions that remain visible on the scene until their tracking effect expires. Persistent spell zones automatically include a DSAZoneRegionBehavior that re-applies spell effects when a token enters the zone or at the start of each combat round, supporting recurring damage and ongoing zone effects.

All spell regions and aura emanations now enforce wall restriction by default, so area effects respect walls and other movement barriers on the scene.

The ring shape type is now available as an area target option alongside sphere, cone, cube, and line.

Token auras now use the Region Emanation API (RegionDocument.createTokenEmanation()), which means emanation regions automatically follow token movement without any manual redrawing. Aura effects are applied and removed via native TOKEN_ENTER and TOKEN_EXIT region events through a new DSAAuraRegionBehavior region behavior type, completely replacing the old distance-polling and manual scene-token iteration. Aura effect application now uses the full advanced effect pipeline, supporting resist rolls, system conditions, macros, delayed effects, and creature links.

The shared DSARegionBehaviorBase base class provides reusable applyEffects(), removeEffects(), validDisposition(), and playSound() methods for all region behavior types, including the existing trap behavior which has been refactored to use the same foundation.

Group Actor

A new "Group" actor type lets GMs and players manage an adventuring party or any collection of characters as a single entity. The group sheet aggregates member stats, skills, inventory, travel, and notes into five dedicated tabs.

Members tab mirrors the GameMasterMenu hero display with portrait, schips, LeP/AsP/KaP bars, expandable details (coin icons, clickable advantages/disadvantages, experience), and bulk action buttons for roll requests, payments, and AP awards. Payment and AP award dialogs use the same hero-selection flow as the GameMasterMenu, including familiar and pet XP scaling. Drag and drop actors onto the sheet to add them; groups cannot contain other groups.

Skills tab shows the best skill value per talent across all members. Each skill row offers one-click group checks and roll requests. Skills are grouped by their talent category; a tooltip on each skill row lists all members and their values.

Inventory tab uses merchant/loot actors as storage locations. Location pills switch between them; dropping a merchant or loot actor onto the sheet links it as a location. A button creates a new loot actor and links it automatically. Item drops to the group sheet are forwarded to the active location.

Travel tab calculates effective overland speed from location-based travel modes (on foot, vehicle, river vessel, sea vessel), modifiers, and configurable forced march percentage. Walking speed is automatically derived from the slowest group member. Speed is shown in both Yard and Meilen (1 Meile = 1000 Yard). Depot locations (vehicles, ships) can be assigned exclusively to a travel mode; when assigned, the location actor's speed replaces the mode's default value and the location name appears on the speed row. A forced march percentage can be set to increase all mode speeds. The active travel mode is selected on the speed table; effective speed is displayed with a full breakdown.

Notes tab provides two rich-text fields (biography and notes) and a button to create a calendar event directly in the calendar system.

The group actor also exposes a GroupAPI extension registry that modules can use to add camp helpers, travel utilities, or other custom actions to the group sheet. A primaryParty world setting marks one group as the active party; the GameMasterMenu shows an "Open Party Sheet" button when a primary party is configured. The TokenScatter utility class provides deploy (scatter member tokens from group token) and reform (converge and delete member tokens) canvas animations.

Improvements

  • Item Enhancement Effects: A new enhancement ActiveEffect type allows permanent item modifications such as materials, creation techniques, and improvements to be represented as data-driven effects on equipment items. Enhancement effects carry a reduced schema (enhancement type, slot cost, crafting roll modifier, crafting time multiplier, craft skill, material cost, special attributes, on-use actions) and apply their changes directly to the parent item's attributes during prepareDerivedData(). They are excluded from actor-level effect application and never transfer to the owning actor. Each equipment item type defines slot limits per enhancement category, enforced via a pre-create hook that also validates change keys against a system.* prefix whitelist. The enhancement type dropdown is filtered per target item type so only categories with available slots are offered. A dedicated DSAEnhancementEffectConfig sheet provides a streamlined four-tab UI (description, details, changes, actions) with the shared wizard/expert dropdown infrastructure. Custom apply logic handles dice-string damage arithmetic (e.g. "1d6+2" → "1d6+4"), slash-separated range multipliers, zone armor protection replication, and special attribute flags (magic, rust-resistant, etc.) that are merged into the item's effect attributes. A compendium helper (DSA5_Utility.getEnhancementEffects()) enables indexed lookups of enhancement AEs from compendium packs by target type and enhancement type. The compendium module's crafting calculator now dynamically loads enhancement effects from the compendium instead of using static modifier tables, making the system fully data-driven and extensible.
  • Hit zones can now be edited directly on opposed result cards, with damage, zone armor, and wound-resistance buttons updating in place.
  • A new public ShapeshiftingAPI now lets macros and modules open the built-in shapeshifting wizard with resolved source/target actors and preset-backed radio defaults.
  • The Active Effect configuration's Changes tab now defaults to a wizard mode that groups effect keys by category (Attributes, Combat, Skills, Magic & Faith, Regeneration, Conditions, Protection & Defense, Weapon/Armor) and hides technical fields behind an expert toggle. The categories are presented as optgroups inside a searchable dropdown; selecting an effect auto-fills the key, type, intended phase, and example value. An expert mode toggle in the tab header restores the full column layout at any time.
  • Advanced effect macros triggered through DSA aura regions and spell template regions now receive a normalized options.regionEvent payload.
  • Payment request handling now relies on package-prefixed native queries such as dsa5.paymentRequest and dsa5.transactionSummary.
  • GMs can now create calendar events directly from the master hotbar and from the calendar picker's Events tab.
  • Actor directory entries and actor sheet window controls now include a GM action to add an actor directly to Dramatis Personae.
  • The primary party group sheet can now be opened directly with the Shift+C keybinding.
  • Social-conflict skill dialogs for Persuasion, Seduction, and Fast-Talk now add a Personae-based Social Contact modifier automatically.
  • The item creation flow now uses a dedicated application dialog instead of an inline prompt with a built-in search field.
  • On-use item macros now live in the item system data as reusable on-use actions instead of a single legacy flag string. Items can define multiple named action entries with their own icon and macro.
  • On-use action dialogs now expose their image row as a real image file picker.
  • On-use actions are now also available on Active Effects. Effects with on-use actions display a badge on the actor's status tab and can be activated from the status effect context menu or the token hotbar. Active effects can also be dropped onto the macro hotbar to create a quick-access macro.
  • On-use actions now support a temporary GM-only activation via right-click.
  • Character inventory sheets now include bulk inventory actions for deleting all inventory items, dropping them onto the current scene as loot, or packing everything into a dropped bag.
  • Trading an item from the actor sheet now opens the shared searchable actor picker instead of the old bespoke trade-target list.
  • ProseMirror editors now include a localized DSA Styles dropdown for quickly wrapping selected content in Master Box, Paper Note, Quote Block, and DSA List containers.
  • Ranged weapons in the combat tab now show reach and reload details in an HTML tooltip on the weapon name instead of an expandable detail row.
  • The @Info journal enricher now allows players to roll knowledge checks directly. Players see a skill roll button; rolling sends a query to the GM who can approve/adjust which QS information to share.
  • GMs can now control which calendar features (calendar, events, personae, questlog) are visible to players via a new feature visibility setting.
  • Enchantment Spell Extensions: Enchantments on items can now carry spell/liturgy extensions. Drag and drop a spell extension from a compendium onto an enchanted item to attach it to the matching enchantment.
  • Post-Roll Rerolls: Active Effects using system.skillModifiers.postRoll.reroll can now permit rerolling up to three dice in a single post-roll reroll activation.
  • Native Effect Expiration: Active effect duration expiration is now handled by Foundry v14's built-in ActiveEffectRegistry instead of the third-party Times-Up module.
  • Condition Level Decay: Leveled conditions with a natural decay rate (Rapture, Stupor, Fear, Paralysis, Confusion) now automatically lose one level per time interval instead of being removed all at once when their duration expires.
  • Maintained Cross-Actor Macro Effects: Maintained spells and rituals can now keep track of macro-created target effects across actors when the macro reports the created ActiveEffect UUID through args.result.maintainedTargets.
  • Weapon Reach Modifier Display: The melee attack dialog now shows the calculated weapon reach modifier next to the opposing weapon size selector and includes it in the dice preview.
  • Unified Situational Modifier Widget: Roll dialogs now use a shared situational modifier widget for skill, combat, spell, regeneration, characteristic, resistance, and falling-damage tests. Situational modifier tooltips now use structured HTML with clearer mechanical effect summaries and lazy-loaded linked rule text.
  • Supporting Skill Burger Menu: Skill test dialogs now include a supporting-skill action in the burger menu. A successful supporting roll applies its bonus directly through the shared situational modifier widget.
  • Forbidden Gates (Verbotene Pforten): Spellcasters with the Forbidden Gates special ability can now activate it from the burger menu during spell and ritual rolls. The flow prompts for a Self-Control check; on success the caster can split spell costs between AE and LP through an interactive cost distribution dialog, on failure the spell fails automatically and the caster pays half costs.
  • Unified Modifier Bracket Formatting: All modifier values across roll dialogs now consistently use square brackets [value].
  • Bag Transfer With Contents: Bags (containers) can now be transferred between actors with all their contents intact. Item parent references are automatically remapped so that the bag structure is preserved on the receiving actor.
  • Action Economy Pips on Hotbar: The actor hotbar now displays small action economy pips when a combatant's turn is active. Base action pips (blue) track actions used this turn; a free action pip (green) tracks the free action; and a movement bar shows distance moved versus speed.
  • Automatic Rapture Tracking: Blessed Ones now automatically gain Rapture (Entrückung) levels when spending Karma Points. Every 10 KaP spent within a rolling 24-hour window adds one level of Rapture (up to max 4).
  • Alternative Calendar Support: The calendar system now supports alternative calendars registered by modules, including the Novadi calendar and the Thorwal calendar.
  • Magical Action Rule Enforcement: Spells and rituals with a magical action type now automatically enforce the corresponding rule restrictions in the roll dialog.
  • Equipment Packages As First-Class Items: Equipment packages are now a dedicated itempackage item type. The /packages chat command lists all available equipment packages from all active compendia.
